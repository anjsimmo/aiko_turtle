TurtleBot Imagineering

A virtual robot that lives in Aiko Chat: <Chat> + <Robot> interfaces, hyperspace-bootstrapped elements started lazily by a LifeCycleManager, ChatSpace membership gated on the <Chat> interface, and an LLM ChatAgent that discovers the robot and drives it — all four phases of the plan, working end-to-end on the shared broker.

Findings worth keeping

  • Cross-element command ordering is not guaranteed on cold start. Each lazily started element drains its own pending queue when it connects, so move/turn sequences can interleave (the amber square above). Fix: serialize robot-side with completion acks.
  • Dependency storage files can carry bootstrap info. The framework leaves "what is stored in each Dependency file?" open; a (bootstrap name protocol command) S-expression was enough to drive lazy loading end-to-end.
  • Robots should only execute messages that start with their mention. Once the ChatAgent began chatting about robots, mention-anywhere triggered accidental commands.
  • Two framework bugs fixed in hyperspace.py: remove() called _destroy() with a phantom argument; update() subscripted a Category instead of .share.
