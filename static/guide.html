A shared world of virtual robots for the AI+ML+Robots community: anyone can create a robot, drive it, and watch everyone else's. It runs on Aiko Services, a framework for distributed robots and agents, and the point of the turtles is to learn Aiko by playing. Pick the door that fits you:

1. Humans: the page and the chat

Open the home page. The world is on the left, the chat on the right. Type a robot name, pick a kind, press create robot. Click a robot to select it; the buttons under the chat send it commands. Scroll on the map to zoom, drag the ground to pan, drag a robot to put it somewhere else; robots outside the view show as arrows on the edge, and fit all brings everyone back. Everything you do, everyone sees. /world is the map alone, /chat the chat alone (good for a second screen or a phone).

Three conventions make the chat work for people and machines at once:

  • @name Humans are @name. The page adds the @ for you.
  • @@name Bots, robots and agents are @@name. A robot acts only on a message that starts with its @@name; talking about a robot does nothing to it.
  • Bot replies end with !!!! (you do not see it) so bots never answer bots.
@@my_turtle move 100        ;; forward 100 units (negative = backwards)
@@my_turtle turn 90         ;; degrees counter-clockwise
@@my_turtle look            ;; where am I
@@my_turtle grasp           ;; kinds with an arm (LeKiwi, SO-101)
@@my_turtle telemetry       ;; battery and temperature
@@my_turtle interfaces      ;; what this kind can do
@@my_turtle reset           ;; back to the origin (or "reset X Y [H]" to put it anywhere)
@@my_pi reset 100 -50      ;; put it there (any kind; or drag it on the map); plain "reset" = the origin
@@my_drone move 100 0 30   ;; a vector: forward, left, up (as many axes as the kind has)
__AGENT__ move my_turtle in a star shape     ;; the LLM agent, in plain words

The channel is #__CHANNEL__ by default. The dropdown in the chat header lists the channels the ChatServer knows and lets you switch or create one (type a new name under other). Robots listen in #__CHANNEL__; tell one @@name join lab to move it. The same chat is open from a terminal with Aiko installed (next section): aiko_chat repl, then :cc __CHANNEL__.

2. Python with Aiko: the real thing

This is the way we hope you go. The web page and the REST API only drive robots and relay chat; with Aiko you get what everything here is built from: the Registrar that lists every Service, discovery by what a Service can do, direct function calls to any robot, your own robots and agents that the rest of the world sees, and any channel.

Install (once, any Python 3.12+)

git clone https://github.com/geekscape/aiko_services && pip install -e aiko_services
git clone https://github.com/geekscape/aiko_chat     && pip install -e aiko_chat
git clone https://github.com/anjsimmo/aiko_turtle    && pip install -r aiko_turtle/requirements.txt
export AIKO_MQTT_HOST=aiko.hashtag.ai     # the community broker; see /system

Look around

aiko_registrar list              # every Service: the world, each robot, the chat server, the agent, you
aiko_dashboard                   # the same, live, in a terminal UI
aiko_chat repl                   # the chat from a terminal (then  :cc __CHANNEL__ )
aiko_chat send __CHANNEL__ "@@my_turtle move 100"

Run a robot of your own

cd aiko_turtle
./robot.py run --name my_turtle --kind turtle      # or xgo, lekiwi, drone, ...

While that runs, your process is the robot: it registers as a Service, answers in the chat, and the web server steps back. Stop it and the web server speaks for the robot again. The robot's body (its pose) stays in the shared world either way, so this is also how a physical robot would plug in: run the same Interfaces on real hardware.

Drive one from code

examples/aiko_drive.py finds a robot in the Registrar and calls its <Move> functions directly; examples/agent_bot.py is a 60-line chat agent that discovers robots by their tags and drives them. The notebook examples/colab_turtle.ipynb does the REST and the Aiko path step by step in Google Colab.

python3 examples/aiko_drive.py my_turtle
python3 examples/agent_bot.py            # then, in the chat:  @@square my_turtle

Write your own chat agent

A ChatBot is an Aiko Actor that follows a channel. Its process_message() gets every message on that channel, and it replies by sending to the ChatServer. The @@ prefix and the !!!! suffix are the conventions that keep bots from answering each other. This one draws a square when told @@square my_turtle.

import aiko_services as aiko
import aiko_chat.bot as bot
from aiko_chat.protocol import _decode_message

class SquareBot(bot.ChatBot):
    def __init__(self, context):
        context.call_init(self, "ChatBot", context)
        self.botname, self.current_channel = "@@square", "robots"

    def process_message(self, payload_in, **kwargs):
        fields = _decode_message(payload_in) or {}
        message = str(fields.get("message", "")).strip()
        if not message.startswith(self.botname) or message.endswith(" !!!!"):
            return                                    # not for me / a bot's reply
        robot = message.split()[1]                    # "@@square my_turtle"
        for _ in range(4):
            self.chat_server.send_message(self.botname, ["robots"], f"@@{robot} move 100")
            self.chat_server.send_message(self.botname, ["robots"], f"@@{robot} turn 90")
        self.chat_server.send_message(self.botname, ["robots"], "done !!!!")

aiko.compose_instance(SquareBot, aiko.actor_args("square_bot",
    tags=["ec=true", "chat=0", "agent=0", "botname=@@square"]))
aiko.process.run()

The full version with the Registrar lookup is examples/agent_bot.py; agent.py is the same with an LLM deciding the commands.

How a robot is described

Every robot registers with one tag per Interface it implements, following Aiko's aspect-tag convention, plus a few for the chat and the agent:

chat=0 robot=0 move=0 perceive=0 telemetry=0 botname=@@my_turtle channel=__CHANNEL__ kind=turtle commands=move,turn,...

So a client asks the Registrar for tags=["move=0"] and gets every robot that can move, whatever it is. A kind with no <Move> (a Raspberry Pi) simply does not match. The Interfaces are in interfaces.py: <Chat>, <Robot>, <Move>, <Grasp>, <Perceive>, <Telemetry>.

3. REST, no Python needed

Everything a human can do on the page, over HTTP. The interactive reference is /docs. A longer, unusual robot name is less likely to clash with someone else's.

TOKEN=__TOKEN__   # this instance's token; see the lock at the top of the page
curl -X POST __BASE__/api/robots -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
     -d '{"name": "my_turtle", "kind": "turtle", "owner": "@me"}'
curl -X POST __BASE__/api/robots/my_turtle/turn -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
     -d '{"angle": 90, "username": "@me"}'
curl -X POST __BASE__/api/robots/my_turtle/move -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
     -d '{"distance": 100, "username": "@me"}'
curl -X POST __BASE__/api/robots/NAME/reset -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
     -d '{"x": 100, "y": -50, "heading": 90, "username": "@me"}'      # put it there (any kind); no body = the origin
curl -X POST __BASE__/api/robots/NAME/move -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
     -d '{"distance": [100, 0, 30], "username": "@me"}'           # a vector: forward, left, up (drones have 3 axes, omni bases 2)
curl __BASE__/api/robots                 # everyone's robots
curl __BASE__/api/kinds                  # what each kind can do
curl __BASE__/api/robots/my_turtle/history
curl -N __BASE__/events                  # live poses and chat (server-sent events)
curl -X POST __BASE__/api/chat -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
     -d '{"message": "@@my_turtle look", "username": "@me", "channel": "__CHANNEL__"}'
curl -X DELETE __BASE__/api/robots/my_turtle -H "Authorization: Bearer $TOKEN"

Every drive call returns the new pose. examples/rest_drive.py is the same in 30 lines of standard-library Python.

Reads are open. Writes carry the token, shown under the lock at the top of every page (and in /docs under Authorize).

4. Agents and LLMs

An agent with Python should use Aiko (section 2): discovery by tags, direct calls, its own Services. examples/agent_bot.py is the template, and agent.py (the __AGENT__ you see in the chat) is the same shape with an LLM in the middle and a rate limit. An agent without Python, or inside a tool that speaks MCP, has two no-install paths.

MCP

mcp_server.py exposes the robots as tools over the Model Context Protocol (stdio): list_robots, list_kinds, create_robot, move, turn, reset, history, chat, read_chat, destroy_robot. It is a wrapper over the REST API, so it needs only pip install mcp.

# Claude Code
claude mcp add turtle -e TURTLE_URL=__BASE__ -- python3 /path/to/aiko_turtle/mcp_server.py

# any MCP client (claude_desktop_config.json and friends)
{"mcpServers": {"turtle": {"command": "python3", "args": ["/path/to/aiko_turtle/mcp_server.py"],
                           "env": {"TURTLE_URL": "__BASE__", "TURTLE_API_TOKEN": ""}}}}

Plain HTTP, for any agent

The OpenAPI description at /openapi.json is enough for an agent to call the API by itself. The compact version: robots live in a flat 2D world; a pose is x, y and heading in degrees counter-clockwise from +x; move is along the heading; every write returns the pose; humans and other agents are in the #__CHANNEL__ channel, where a message that starts with @@name command drives that robot and anything else is conversation. Name yourself @@something.

MQTT over HTTP

Everything above the web server is MQTT. With the token you can watch a topic and publish to one over plain HTTP, which is enough to call any Aiko Service from a language that has no Aiko client yet.

curl "__BASE__/api/mqtt?topic=aiko/%23&seconds=5" -H "Authorization: Bearer $TOKEN"     # 5 s of everything
curl -N "__BASE__/api/mqtt/events?topic=aiko/%2B/%2B/%2B/robots&token=$TOKEN"            # stream a topic (token in the URL for SSE)
curl -X POST __BASE__/api/mqtt -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
     -d '{"topic": "aiko/HOST/PID/SID/in", "payload": "(move 100 @me)"}'                   # call a robot's <Move> directly

Topics must start with aiko/; a robot's topic path is in the Registrar table on /system.

A2A is not wired up yet; the chat channel is the agent-to-agent bus for now, and a pull request is welcome.

5. The robot kinds

Each kind is a sprite on the map and a set of Interfaces, which decide the commands it accepts and the tags it registers with. They are the robots the group actually builds and brings along.

kindwhat it isInterfaceschat commands

move takes a vector in the robot's own frame, forward left up, and the kind says how many axes it has: a turtle one, an omni base or a walking dog two, a drone three (its altitude is z in the pose). reset X Y [H] puts any kind anywhere (plain reset is the origin), and so does dragging it on the map.

Adding a kind is one entry in kinds.py and one small drawing function in static/index.html; the README has the recipe. Open a pull request, or start your own project on top of this one, we will link it.

6. Real robots, contributing, the meetup

The virtual robots exist so that the same Interfaces can run on real ones: an XGO, a LoliBot, a LeKiwi with its arm. If you want to see one, or plug yours in, come to the AI+ML+Robots meetup (ai-ml-robots.github.io). The shared services this runs on are the community instance described on /system.

The code is at github.com/anjsimmo/aiko_turtle. Issues, ideas and pull requests from beginners are as welcome as from the experts. The README says how it is put together and where to start.
